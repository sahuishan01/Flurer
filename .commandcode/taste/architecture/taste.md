- Tauri: lifecycle/run-event handlers that can execute before `app.manage()` must use `app.try_state::<T>()` instead of `app.state::<T>()` (which panics with "state() called before manage()"). Reachable in Flurer via the "Always run as admin" path: accepting the UAC prompt makes the unelevated instance call `app.handle().exit(0)` inside `.setup()` BEFORE reaching `manage(AppState)`, and that exit fires `RunEvent::Exit`, whose window-settings save handler used `app.state::<AppState>()` and crashed (v0.4.187). A "state() called before manage()" crash on one machine but not another points at a settings-dependent setup early-exit path, not platform flakiness — trace the setup exit paths against the manage() call-site order. v0.4.188 proved the guard must be a SWEEP, not a point patch: guarding only the settings-save site still crashed on the user's machine because the same Exit handler also calls `sizecache::flush(app)`, which had its own unconditional `app.state()` — and the guarded settings block itself was skipped on that path (no main window yet) while `flush` ran unconditionally. Before releasing such a fix, grep for EVERY call site of the panicking pattern (`.state::<`) and audit all callbacks reachable in the pre-manage window (single-instance handler, global-shortcut handler, spawn_new_window), guarding each with `try_state` + early return and a site comment stating the rationale.
